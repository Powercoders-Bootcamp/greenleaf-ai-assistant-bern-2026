# Team Charter

> Archive note: This is a historical team-process document. For current product and architecture decisions, use the active docs in `docs/`.

## GreenLeaf Logistics - Beat-Bot Team

## 1. Team Name

**Team Name:** PolicyAI Squad

## 2. Team Mission

Design and deliver a reliable, secure, and source-driven assistant that automates repetitive employee questions while protecting trust and safety.

## 3. Team Purpose

- Translate business needs into a working AI product
- Build a trustworthy assistant grounded in company policy
- Reduce repetitive operational interruptions
- Deliver a high-quality MVP within the project timeline

## 4. Team Roles and Responsibilities

### Product Owner

- define product vision and priorities
- own backlog and user-story refinement
- align implementation with stakeholder expectations

### Scrum Master

- facilitate ceremonies
- remove blockers
- support healthy team communication

### Technical Architect

- define system architecture and technical boundaries
- guide integration across frontend, backend, data, and AI

### Developers

- implement features according to requirements
- collaborate on APIs and system integration
- write maintainable, testable code

### QA / Quality Engineer

- define test strategy
- validate safety, correctness, and edge cases
- support evaluation of AI outputs

## 5. Team Values

- accuracy over speed
- accountability
- transparency
- simplicity
- continuous improvement
- user trust first

## 6. Working Agreements

- blockers are communicated early
- major decisions are documented
- code reviews are required for important changes
- no work is considered complete without shared visibility

## 7. Definition of Done Reminder

A story is not considered done unless:

- acceptance criteria are met
- code is reviewed
- safety expectations are satisfied
- source references are correct where applicable
- relevant documentation is updated
